# เกมทีมและช่วงเฉลย — 10 กันยายน 2026

ทำงานและผ่านการทดสอบบน local production build กติกาใหม่ใช้เฉพาะห้องที่สร้างใหม่ (`rulesVersion: 2`) ห้องเก่าคงสูตรเดิม

## กติกา

- คะแนนทีม = ผลรวมคะแนนคำตอบของสมาชิกที่มีสิทธิ์ ÷ จำนวนสมาชิกที่ล็อกตอนเริ่ม ไม่มีโบนัสความเร็ว
- หัวหน้าทีมคือสมาชิกที่ยังอยู่และเข้าก่อน ใช้ ID ตัดสินหากเวลาเข้าเท่ากัน
- พลังทีมใช้ได้หนึ่งข้อทั้งเกม เพิ่มคะแนนคำตอบถูกของทีมในข้อนั้น 50% หัวหน้าที่มีสิทธิ์ร่วมคะแนนต้องกดก่อนคำตอบแรกของทีมและก่อนหมดเวลา
- คำตอบแรกของทีมปิดโอกาสใช้พลังย้อนหลัง แม้ตอบผิดหรือเป็นสมาชิกเข้าช้า การกดพลังกับส่งคำตอบพร้อมกันยึดลำดับที่เซิร์ฟเวอร์บันทึก
- ข้อสุดท้ายคูณ 1.5 รวมพลังทีมเป็น 2.25 ห้องข้อเดียวถือเป็นข้อสุดท้ายด้วย
- ตอบผิด ไม่ตอบ หรือเข้าหลังเริ่มได้ศูนย์ ไม่มีการหักทีมอื่นหรือตัวคูณลับให้ทีมท้ายตาราง
- สำเนาคำถาม คำตอบ ตัวเลือก คะแนน และเวลาตอนสร้างห้อง การแก้คลังไม่เปลี่ยนห้องนั้น รูปภาพยังอ้างอิง URL เดิม จึงควรเก็บไฟล์ภาพจนจบห้อง

ตัวอย่างโจทย์ 10 คะแนน ทีม 4 คน: ตอบถูกในข้อสุดท้ายพร้อมพลังได้คะแนนดิบ 22.5 และช่วยคะแนนเฉลี่ยทีม 22.5 ÷ 4 = 5.625 (แสดง 5.63) หากตอบถูกครบทั้งทีม คะแนนเฉลี่ยรอบนั้นเป็น 22.5 เท่ากับทีม 2 คนที่ตอบถูกครบเช่นกัน ผลรวมตัวเลขรายคนที่ปัดแล้วอาจต่างจากคะแนนทีม 0.01 เพราะทีมรวมคะแนนดิบก่อนปัด

## หน้าจอ

ทั้งครูและนักเรียนเห็นคะแนนถึงข้อก่อนหน้าระหว่างเปิดรับ/ล็อกคำตอบ แล้วเปิดคะแนนรอบปัจจุบันตอนเฉลย เครือข่ายและ polling ทำให้แต่ละเครื่องอาจรับผลต่างเวลากันเล็กน้อย

ครูเห็นพลุเมื่อมีผู้ตอบถูก นักเรียนตอบถูกเห็นพลุพร้อมคะแนนที่ช่วยทีม ตอบผิดเห็นข้อความเฉลย พลุ 6 ชุดจบใน 4.2 วินาที ไม่รับคลิก ไม่ล็อกปุ่ม และหยุดเมื่อซ่อนแท็บ อันดับขยับจากข้อมูลจริง คะแนนนับขึ้นใน 900ms โปรแกรมอ่านหน้าจออ่านค่าจริง การรีเฟรชหน้าเฉลยไม่เล่นพลุซ้ำ

แสดงส่วนคะแนนคำตอบและโบนัสพลังหลังเฉลย ใช้เอฟเฟกต์เต็ม ไม่มีเมนูเลือกเบา/ลดการเคลื่อนไหว คงรองรับการตั้งค่าลดการเคลื่อนไหวของระบบปฏิบัติการด้วยผลลัพธ์แบบคงที่ และมีภาพสำรองเมื่อ WebGL ใช้ไม่ได้

## ความถูกต้องในการบันทึก

Local ใช้คิวล็อกและเขียนไฟล์ atomic ใน process เดียว ตรวจสิทธิ์/session/question ภายใน lock ไม่รองรับหลาย server process เขียนไฟล์เดียวกัน

Supabase ใช้ RPC `activate_classroom_power` และ `submit_classroom_answer` ล็อกแถว session เดียวกันด้วย FOR UPDATE แล้วบันทึกคำตอบและคะแนนใน transaction เดียว ตัวคูณมาจากฐานข้อมูล เก็บ base_score_awarded / power_bonus_awarded และจำกัด execute ให้ service_role คำตอบถูกผิดตรวจในเซิร์ฟเวอร์จากสำเนาคำถาม

ห้องเก่าคงทางบันทึกเดิม การแก้ครั้งนี้ไม่ได้ย้ายคำสั่งเริ่ม/เปลี่ยนข้อของครูหรือระบบ join ทั้งหมดเข้า transaction ใหม่

- Dependency audit หลังเพิ่มเครื่องมือทดสอบ SQL: 0 vulnerabilities
