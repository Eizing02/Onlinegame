# Boss Raid: จังหวะต่อสู้และธีมคลาสสิก

งานนี้ทำตามแผนที่ผู้ใช้อนุมัติ: เวลารวมเดินต่อระหว่างต่อสู้ ช่วงแสดงผลร่วมกัน 3 วินาทีทุกตัวละคร เลือกซ้ำได้ และยืนยันอัตโนมัติหลังเตรียมคำตอบ 5 วินาที

## สิ่งที่เปลี่ยน

- คำตอบที่บันทึกสำเร็จปิด dialog เพื่อเปิดสนามจริง เอนจินเล่นเหตุการณ์ของคำตอบนั้นก่อนงานของเพื่อน พร้อมติดตามคลิปโจมตี กระสุน โดนตี/ตาย และฟื้น HP ก่อนกลับไปโจทย์ถัดไป
- RPC ส่ง `presentation` ที่มีรหัสคำขอ เหตุการณ์ที่เกิดใน transaction นี้ ระยะเวลา และเวลาที่ข้อถัดไปเปิดได้ Snapshot งดส่งโจทย์ระหว่างช่วงรอ และเซิร์ฟเวอร์ปฏิเสธคำตอบใหม่ก่อนถึงเวลา คำขอซ้ำคืน ledger เดิม
- เวลาที่แสดงอิง deadline/serverNow ใช้นาฬิกา monotonic ไม่เริ่มใหม่เมื่อเปลี่ยนข้อหรือรีเฟรช กรอบเวลาเต้นช้าใน 30 วินาทีสุดท้าย ตัวเลขยังอ่านได้
- ปาร์ตี้แสดงสมาชิกทีมตัวเอง ชื่อ ตัวละคร HP และผู้เล่นปัจจุบัน ย่อ/ขยายได้ทั้งในห้องและใน native dialog ของคำถาม
- ห้องกติกา v2 เลือกตัวซ้ำได้ 1–5 คนตามขนาดทีมเดิม ตัวที่เลือกมีออร่าทอง ตัวอื่นเป็นขาวดำเฉพาะภาพและยังคลิกได้ การบันทึกล้มเหลวคืนการเลือกที่เซิร์ฟเวอร์ยืนยันไว้
- ช้อยที่เลือกใช้สีแดงไวน์และแถบ 5 วินาที เปลี่ยนช้อยเริ่มนับใหม่ ยืนยันเองส่งทันที ยกเลิกการเลือกหยุดนับ คำตอบแบบพิมพ์เริ่มนับเมื่อกดตรวจคำตอบ ไม่เริ่มระหว่างพิมพ์
- สลับแท็บหยุดการส่งอัตโนมัติ กติกา visibility เดิมยังทำงานในช่วงตอบ/ยืนยัน หมดเวลารวมหรือครูจบเกมไม่ต่อเวลา 5 วินาทีให้
- ธีมครีม `#F5EFE1`, เบจ `#E5D3AF`, แดงไวน์ `#790D16`, ฟ้าหม่น `#AEC4D4` ครอบคลุมหน้าครู นักเรียน Classic/Boss Raid บัญชีและข้อผิดพลาด เฉดหมึกเข้มรักษาความต่างสี ตัวละครเดิมไม่ถูกย้อม ภาพฉากปรับบรรยากาศครั้งเดียวในแคช texture ที่มีขอบเขตและยังใช้ geometry/alpha เดิม

## ขอบเขตสำคัญ

สูตรคะแนน ความเสียหาย ฟื้น HP เวลาปราบบอส และ deadline ไม่เปลี่ยน Google Login/RBAC ไม่เปลี่ยน Classic ยังให้ครูควบคุมลำดับข้อและเฉลยตามเดิม การยืนยัน 5 วินาทีและช่วงต่อสู้เป็นของ Boss Raid v2

ห้องเดิมเก็บ `rules_version=1` ไม่แปลงย้อนหลัง ห้องใหม่หลัง migration 010 ใช้ v2 ห้อง v1 ยังบังคับเลือกไม่ซ้ำใน RPC ภายใต้ล็อกเดิม ไฟล์ migration 001–009 และข้อมูลเก่าไม่ถูกแก้

ห้อง v1 ยังยืนยันคำตอบด้วยตนเองและใช้คิวต่อสู้เดิม หากคำตอบไม่มีชุด `presentation` ระบบจะไม่เปิดคิว priority ว่างไปกลบอนิเมชันเดิม ส่วน v2 ใช้ชุดเหตุการณ์ที่ตรงกับคำตอบและช่วงรอที่เซิร์ฟเวอร์บังคับ

ช่วงต่อสู้ปกติใช้ 3 วินาที เอนจินติดตามจบคลิปจริงและแยกคิวของคำตอบตัวเอง กรณี renderer/ภาพไม่พร้อมมีทางเดินสำรองสูงสุด 3.5 วินาทีเพื่อไม่ค้างหน้า เครื่องที่โหลดช้าหรือเครือข่ายช้ายังอาจมีเวลารอเพิ่ม จึงไม่ได้อ้างว่าทุกอุปกรณ์มี latency เท่ากัน คำแนะนำเวลาในหน้าสร้างห้องรวมเวลาต่อสู้แล้ว

## SQL และการเผยแพร่

**มี SQL ใหม่ แต่ไม่ได้รันบน Production และไม่ได้ push/deploy ในงานนี้**

1. ต้องมี migration 009 Boss Raid อยู่แล้ว
2. ตรวจไฟล์ `supabase/migrations/010_raid_pacing_and_duplicate_heroes.sql` แล้วรันหนึ่งครั้งใน Supabase SQL Editor เมื่อพร้อมอัปเดตระบบ ไฟล์นี้ใช้ transaction และไม่มีคำสั่งลบข้อมูลห้อง/บัญชี/คำถาม
3. ใช้ `scripts/boss-raid/verify-presentation.sql` ตรวจแบบอ่านอย่างเดียว: เวอร์ชันกติกา คอลัมน์ช่วงรอ สิทธิ์ และการไม่เปิดตาราง Raid ผ่าน Realtime publication
4. เผยแพร่ frontend จากชุดโค้ดนี้เมื่อได้รับอนุญาต ไม่ต้องเปลี่ยน Google Cloud Console, OAuth callback, Supabase Google provider หรือเพิ่ม environment variable
5. ทดสอบห้องใหม่: นักเรียนสองคนเลือกตัวเดียวกัน เลือกช้อยรอ 5 วินาที เห็นการต่อสู้ ก่อนเห็นข้อใหม่ และยังเปิดปาร์ตี้ได้ขณะตอบ
