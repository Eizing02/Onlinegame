# Rules version 1

| เหตุการณ์ | ผลที่เซิร์ฟเวอร์ตัดสิน |
|---|---|
| เริ่ม | Hero HP 100; Boss max HP = ceil(0.75 × N × 10 × ผลรวมคะแนนคำถาม) |
| มี HP และตอบถูก | คะแนน Raid = คะแนนข้อ; damage = min(Boss HP ที่เหลือ, 10 × คะแนนข้อ) |
| มี HP ตอบผิด และบอสยังอยู่ | เสีย HP clamp(round(150 / จำนวนข้อ), 5, 20) |
| HP 0 และตอบถูก | คะแนน Raid/damage 0; สุ่มเพื่อนคนอื่นที่ HP <100 ฟื้น 10 HP ไม่เกิน 100 รวมเพื่อนที่ HP 0 |
| ทีมคนเดียว HP 0 ตอบถูก | ฟื้นตัวเอง 10 HP ไม่ได้คะแนนหรือ damage ในข้อนั้น |
| ทีมหลายคนแต่เพื่อนทุกคน HP 100 | ไม่ฟื้นตนเอง ไม่มีเป้าหมาย heal; คำตอบถูกยังนับผลเชิงวิชาการ |
| บอสถูกปราบแล้ว | damage/การตอบโต้ 0; ผู้มี HP ตอบข้อที่เหลือยังได้คะแนน ผู้ HP 0 ยัง heal ได้ |
| ข้ามเพราะ visibility | คะแนน/damage/heal 0, ไม่เสีย HP, cursor เดินหนึ่งข้อ |

N คือผู้เล่นจริงที่ล็อกตอนเริ่ม ไม่มี bot ไม่เปลี่ยนเมื่อ disconnect หรือ late join ชุดที่คะแนนรวม 0 ห้ามเริ่ม คะแนนเชิงวิชาการและจำนวนข้อถูกนับแยกจากคะแนน Raid เสมอ

ไม่มี Team Power ตัวคูณข้อสุดท้าย หรือคะแนนตามความเร็วของ Classic ใน Raid

## สองอันดับ

- คะแนนเฉลี่ย = คะแนนรวมทีม / N ล็อก เช่น 1 คนได้ 100 และ 5 คนได้รวม 500 ได้เฉลี่ย 100 เท่ากันและอันดับร่วม เปรียบเทียบผลคูณไขว้ ไม่ตัดสินจากเลขที่ปัดให้แสดง
- Kill duration = defeated_at ครั้งแรกที่ HP ลง 0 − started_at จากเซิร์ฟเวอร์ เท่ากันถึงมิลลิวินาทีได้อันดับร่วม ทีมยังไม่ปราบเรียงความคืบหน้าและไม่มีอันดับ kill
- ความแม่นยำ = ข้อถูกเชิงวิชาการ / (N × จำนวนข้อ) รวมข้อยังไม่ทำในตัวหาร แสดงจำนวนข้อถูกด้วย

สุ่มลำดับคำถามอาจทำให้เวลา kill ต่างกันเมื่อคะแนนข้อไม่เท่ากัน แต่ทุกคนได้ชุดเดียวกันครบ ไม่มีเวลารายข้อ และอันดับเฉลี่ยใช้คะแนนทั้งชุด ชุดที่คำถามอ้างอิงข้อก่อนหน้าไม่เหมาะกับ v1 ซึ่งยังไม่มี grouping/opt-out shuffle

## Visibility

ใช้ `document.visibilitychange` เฉพาะ popup ที่ตอบได้ ไม่ใช้ `blur` ระหว่างส่งคำตอบ/fade/รอโหลด/ผลไม่ตรวจ เวลาเกมไม่หยุด

2999ms และ 3000ms ไม่เตือน; มากกว่า 3000ms เตือนครั้งที่ 1/2 และ 2/2 ครั้งที่ 3 ข้ามเฉพาะคำถามที่มี questionId/displayIndex ตรงกับ cursor ปัจจุบัน เหตุการณ์ UUID ซ้ำไม่เพิ่มเตือน ข้อใหม่เริ่ม 0 และเหตุการณ์ข้อเก่าไม่มีสิทธิ์ข้ามข้อใหม่ Answer กับ skip ใช้ lock/ledger เดียวกัน จึงมี terminal outcome อย่างมากหนึ่งรายการ

Browser บอกได้เพียงการมองเห็นหน้า ระยะเวลาเป็นค่าที่ client รายงาน ไม่พิสูจน์เจตนาหรือการใช้ AI การสลับระบบ/สายเข้า/เครือข่ายอาจทำให้ข้อมูลคลาดเคลื่อน ครูปิดการเตือนก่อนเริ่มได้และดู audit 200 เหตุการณ์ล่าสุด ฐานข้อมูลยังเก็บเหตุการณ์ทั้งหมดของรอบ

v1 ไม่มีการย้อนคะแนนที่อาจทำลาย ledger ให้ครูบันทึกเหตุผลกรณีขัดข้อง และใช้รายงานข้อถูกเชิงวิชาการ/CSV ประเมินหรือจัดรอบใหม่ ยังไม่ลบหรือแก้ประวัติคำตอบเงียบ ๆ
