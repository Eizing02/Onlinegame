# ผลการแก้ระบบเข้าสู่ระบบและปรับประสบการณ์เกม

อัปเดตเกมทีมรอบถัดมา: ดู [GAMEPLAY-UPGRADE-TH.md](GAMEPLAY-UPGRADE-TH.md) สำหรับพลังทีม ข้อสุดท้าย ×1.5 เอฟเฟกต์เต็ม และผลทดสอบล่าสุด ซึ่งแทนรายละเอียดตัวเลือกระดับเอฟเฟกต์ในบันทึกก่อนหน้านี้

ตรวจยืนยันวันที่ 9 กันยายน 2026 ในเครื่อง Windows ด้วย production build และ Chromium ข้อมูลทดสอบทั้งหมดแยกใน `tmp/e2e-data` และ `tmp/regression-*` ไม่ใช้บัญชีนักเรียนจริง

เพิ่มเติมวันที่ 10 กันยายน 2026: แก้และทดสอบ parser ของสคริปต์นำเข้า Supabase ให้ตรงกับกติกาบทบาทของแอป โดยยังไม่ได้รันการนำเข้าข้อมูลจริง

เอกสารนี้เป็นสถานะหลังแก้ ส่วน `SYSTEM-REVIEW-TH.md` เป็นบันทึกการตรวจระบบก่อนแก้ ไม่ใช่รายการปัญหาที่ทุกข้อยังคงอยู่

## สิ่งที่แก้แล้ว

### การเข้าสู่ระบบและบทบาท

1. เปลี่ยน cookie Base64 ที่แก้ไขเองได้เป็น JWT HS256 ลงลายเซ็นด้วย jose อายุ 8 ชั่วโมง เก็บใน cookie `rqg_session_v2` แบบ HttpOnly / SameSite=Lax / Secure เมื่อ production
2. อ่านบทบาทจากบัญชีต้นทางจริงหลังตรวจลายเซ็น ไม่รับบทบาทจากข้อมูลที่เบราว์เซอร์ส่งมา การเปลี่ยนรหัสผ่านหรือบทบาททำให้ session เดิมใช้ไม่ได้
3. จัดรูปแบบรหัสผู้ใช้ รองรับช่องว่างหัวท้าย ตัวพิมพ์เล็ก/ใหญ่ และเลขไทย แต่เก็บรหัส canonical เดิมเพื่อไม่ทำให้ความเป็นเจ้าของชุดคำถามและห้องเก่าเปลี่ยน
4. อ่าน CSV ที่มี BOM, quoted comma, escaped quote และ newline ได้ ตรวจบัญชีซ้ำและบทบาทผิดแทนการตั้งเป็นนักเรียนเงียบ ๆ
5. ใช้ guard กลางในหน้าครู/นักเรียน รวมทั้งหน้าชุดคำถามที่เคยมี guard เก่าและ redirect ภาษาไทยตรง ๆ จนเกิด HTTP 500
6. เข้าหน้า `/` หรือ `/login` ขณะมี session จะไปหน้าที่เหมาะสม กลับเข้าห้องที่ยังไม่จบได้ บัญชีครูที่เข้าหน้านักเรียนจะกลับหน้าครู
7. Login แสดงข้อผิดพลาดในฟอร์ม เก็บรหัสผู้ใช้ไว้ มีสถานะกำลังส่ง และข้อความอ้างอิงเมื่อการตั้งค่าหรือฐานข้อมูลมีปัญหา Log ไม่พิมพ์รหัสผ่านหรือ token
8. Header แสดงบทบาท ชื่อบัญชี และออกจากระบบ เมื่อบัญชีใน browser เปลี่ยนจะมี dialog ให้เปิดหน้าใหม่ ตรวจเมื่อกลับมาโฟกัสและทุก 15 วินาที ความล้มเหลวของเครือข่ายอย่างเดียวไม่ทำให้ logout
9. API ของห้องตรวจสิทธิ์และความเป็นเจ้าของจริง เอา teacher access token ที่อนุมานจาก student snapshot ออก คำสั่งเกมจาก client มี session identifier เพื่อปฏิเสธคำสั่งจากหน้าบัญชีเก่า
10. สคริปต์ seed เดิมตีความ role ภาษาไทยว่าเป็นนักเรียน แก้ให้รองรับครู/นักเรียนอย่างชัดเจน ปฏิเสธ role ผิด บัญชีซ้ำและแถวไม่ครบก่อนเริ่มเขียนฐานข้อมูล และไม่ trim รหัสผ่าน มีการทดสอบเทียบกติกากับ parser ของแอป

### ความสม่ำเสมอระหว่างเล่น

- ส่งรหัสคำถามและ session ของเกมไปพร้อมคำตอบ เพื่อปฏิเสธคำตอบที่หลงจากข้อเก่า
- ไม่รับ snapshot เก่ามาทับ snapshot ใหม่ และไม่ทับห้องเดิมด้วย session อีกห้องที่บังเอิญใช้รหัสซ้ำ
- เรียงห้อง local ให้เลือกห้อง active/ล่าสุดก่อนห้องที่จบแล้ว
- ซ่อนคะแนนใน nested team ก่อนเฉลยด้วย ไม่ใช่ซ่อนเพียงค่าที่ใช้แสดงผล
- Local adapter ใช้คิวร่วมใน Node process และเขียน JSON แบบ temporary file + rename ป้องกันข้อมูลหายจาก read/modify/write พร้อมกัน
- หยุด polling ขณะ tab ซ่อน ลดการอ่านและงานที่ไม่จำเป็น ใช้ polling เป็นทางสำรองเมื่อ realtime ใช้ไม่ได้
- ไม่เปิดเสียงเองเมื่อกดตอบ และไม่เล่นเอฟเฟกต์เฉลยซ้ำเมื่อ refresh หน้าเฉลย

### ภาพและการใช้งานตาม Impeccable

ใช้แนวทาง audit, adapt, harden, animate, optimize และ polish โดยคงธีม sci-fi เดิม

- ฉากดาวเคราะห์ 3D ในหน้าเข้าสู่ระบบบนจอใหญ่และหน้ารอเกม ถ้วยรางวัล 3D เมื่อจบเกม พื้นหลังดาวเคลื่อนช้าและ transition เปลี่ยนคำถามสั้น ๆ
- เลือกเอฟเฟกต์เบา/เต็ม/ลดการเคลื่อนไหวได้ บันทึกตัวเลือกในเครื่อง และเคารพ `prefers-reduced-motion`
- Three.js โหลดแยกเมื่อฉากมองเห็น จำกัด pixel ratio ที่ 1 / 1.5 และจำกัดการวาดที่ 24 / 45 ครั้งต่อวินาทีตามโหมด หยุดและคืนทรัพยากรเมื่อฉากไม่ใช้งาน
- มี static fallback เมื่อ WebGL ใช้ไม่ได้ โดยฟอร์มและเกมยังใช้งานได้
- แทน GIF เฉลยและรูปอันดับขนาดใหญ่ด้วย feedback และ 3D ที่ใช้ทรัพยากรร่วมกัน
- ใช้ Noto Sans Thai, เพิ่ม contrast ของปุ่มหลัก, ช่องกรอก 16px, ปุ่มสัมผัสสูงอย่างน้อย 44px, focus ring และ skip link
- จัดส่วนควบคุมครูก่อนรายชื่อบนจอเล็ก ปรับฟอร์มเข้าสู่ระบบเป็นคอลัมน์เดียว
- ผลการแข่งขันและรูปขยายใช้ native dialog รองรับ Escape และจัดการ focus ตารางผลคะแนนเลื่อนด้วยคีย์บอร์ดได้
- MathText ส่ง HTML พร้อม MathML สำหรับเทคโนโลยีช่วยอ่าน
- ลบตัวเลขห้อง/คะแนนตัวอย่างที่อาจเข้าใจว่าเป็นข้อมูลจริงออกจากหน้าเข้าสู่ระบบ

## ก่อนใช้กับระบบจริง

1. ตั้ง `AUTH_SESSION_SECRET` เป็นค่าลับสุ่มอย่างน้อย 32 bytes ที่คงเดิมข้าม deployment และตรงกันทุก instance อย่าใช้ secret ของชุดทดสอบ ตัวอย่างสร้างค่า: `node -e "console.log(require('node:crypto').randomBytes(48).toString('hex'))"`
2. ตรวจ `DATA_BACKEND` ให้ตรงกับระบบจริงและไม่สลับไปมาเอง ค่า production ที่ไม่มี secret จะไม่ยอมเข้าสู่ระบบ ใน development เท่านั้นจึงสร้าง secret ลง `data/.auth-secret` อัตโนมัติ
3. บัญชีควรมี role เป็น `TEACHER` / `STUDENT` (หรือ `ครู` / `นักเรียน`) ชัดเจน รหัสที่ต่างกันเฉพาะตัวพิมพ์เล็กใหญ่ต้องไม่ซ้ำกัน บัญชีครูแบบเดิมที่ role ว่างแต่ grade เป็น TEACHER/ครูยังรองรับ
4. ผู้ใช้ที่มี cookie รุ่นเดิมต้องเข้าสู่ระบบใหม่หนึ่งครั้งหลังอัปเดต
5. ถ้าใช้ Supabase ให้นำ migration `006_private_game_data.sql` ไปทดสอบและรันบนฐานข้อมูลเป้าหมาย แล้วทดสอบด้วยครู/นักเรียนสอง browser อีกครั้ง

Migration 006 ยกเลิกการอ่านข้อมูลเกมและเฉลยโดย anon/authenticated โดยตรง แต่ service role ของ Next ยังเข้าถึงได้ สร้าง `game_session_updates` สำหรับ realtime ซึ่งมีเพียง session UUID และ timestamp เมื่อมีสัญญาณ client จึงขอ snapshot ที่ตรวจสิทธิ์ผ่าน Next หากยังไม่ลง migration เกมจะใช้ polling สำรอง แต่ช่องอ่านข้อมูลสาธารณะจาก schema เก่ายังไม่ได้ปิด

**ยังไม่ได้ deploy หรือรัน migration กับ Supabase จริง** เพราะ workspace นี้ไม่มีค่าการเชื่อมต่อและบัญชีจริงให้ยืนยัน SQL ถูกเตรียมไว้แล้ว แต่ยังไม่อ้างว่า integration ฐานข้อมูลจริงผ่าน

## ข้อจำกัดที่ยังต้องแยกจัดการ

- Local lock รองรับ Node process เดียว ไม่ใช่ distributed lock สำหรับหลาย server/serverless
- Supabase การเข้าทีม/การคำนวณคะแนนยังมี read-modify-write หลายขั้นตอน ต้องทำ transaction/RPC หากต้องรับคำขอพร้อมกันมากอย่างเข้มงวด ชุดทดสอบ concurrency ข้างต้นยืนยันเฉพาะ local adapter
- ระบบยังเก็บรหัสผ่านในแหล่งบัญชีรูปแบบเดิม ยังไม่ได้ migrate เป็น password hash หรือเพิ่ม distributed login rate limit
- คำถามยังอ่านจาก question bank ไม่ได้ snapshot ชุดคำถามลงห้อง จึงไม่ควรแก้/ลบข้อที่ห้อง active ใช้อยู่จนกว่าจะเพิ่มการ freeze/versioning
- เมื่อเวลาหมด server ปฏิเสธคำตอบ แต่ครูยังเป็นผู้สั่งเฉลย/ไปข้อถัดไป ไม่ได้เพิ่ม auto-advance
- ยังไม่ได้ทดสอบ Safari/iOS จริง, เครื่องโรงเรียนจริง, projector และเครือข่ายโรงเรียน จึงไม่รับรอง WCAG ทั้งระบบหรือ FPS บนทุกอุปกรณ์จาก axe/Chromium เพียงอย่างเดียว
