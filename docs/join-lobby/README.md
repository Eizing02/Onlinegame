# ปรับหน้าห้อง ทีม และสถานะการโหลด — 15 ตุลาคม 2026

## สิ่งที่เปลี่ยน

1. เมื่อค้นพบห้อง ช่องกรอกรหัสจะหายไป เหลือข้อมูลห้องและปุ่มเปลี่ยนห้อง นักเรียนเดิมเห็นทีมปัจจุบันและกลับเข้าเกมได้
2. เลือกทีมก่อน แล้วกด **ยืนยันเข้าทีม** จึงบันทึกสมาชิก กรอบทอง เงา เครื่องหมายถูก และข้อความบอกทีมที่เลือก ปุ่มสุ่มเพียงเสนอทีมให้ยืนยัน ไม่เข้าทีมเอง
3. Boss Raid เปิดแท็บ **ทีมของฉัน** ได้ตั้งแต่ lobby หัวหน้าทีม (สมาชิกคนแรกที่ยังไม่ออก) เปลี่ยนชื่อ 2–30 ตัวอักษรได้ก่อนเริ่มเกม หน้าครูและเพื่อนซิงก์ชื่อใหม่ การหลุดชั่วคราวไม่เปลี่ยนหัวหน้าทีม
4. ตัวโหลดวงกลมกลางจอสำหรับฟอร์มเข้าสู่ระบบ/บัญชี/ข้อสอบ/สร้างห้อง/เข้าทีม และคำสั่งเกมหลัก รวมการส่งคำตอบใน native dialog การซิงก์สถานะตามรอบไม่บังจอ โหลดฉากและทีมครูมีตัวโหลดในพื้นที่นั้น
5. สลับแท็บ Raid ด้วยการเลื่อนตามทิศทาง เก็บชื่อทีมที่กำลังพิมพ์ข้ามแท็บ ฉากนักเรียนยัง mounted ขณะเปลี่ยนแท็บ ปาร์ตี้ เพลง ภาพ และการต่อสู้เดิมคงอยู่
6. Boss Raid สุ่มเฉพาะคำถามและเก็บลำดับไว้ต่อผู้เล่น ช้อยปรนัยและถูก/ผิดเรียงตามที่ครูสร้างด้วย ID เดิม Classic คงลำดับคำถามและช้อยตามเดิม

เวลารวมยังเดินต่อ ช่วงยืนยันคำตอบห้าวินาทีและช่วงต่อสู้สามวินาทียังใช้กติกาเดิม ไม่มีการแก้สูตรคะแนน HP หรือข้อมูลข้อสอบเดิม

## SQL สำหรับรุ่นนี้

ผู้ใช้แจ้งว่ารัน SQL 012 แล้ว และอนุญาตให้พุชเข้า `main` เมื่อ 15 ตุลาคม 2026 การติดตั้ง Production เป็นข้อมูลจากผู้ใช้ ผู้ช่วยไม่ได้เชื่อมต่อฐานข้อมูลจริงเพื่อตรวจยืนยัน

สำหรับการติดตั้งฐานข้อมูลอื่น หากติดตั้งถึง **011** แล้ว ให้รันเฉพาะ **012_raid_lobby_and_choice_order.sql** เพิ่มเติม ไม่ต้องรัน 001–011 ซ้ำ ไม่ต้องตั้งค่า Google Cloud ใหม่ และไม่มี environment variable ใหม่

ลำดับนำขึ้นใช้งาน:

1. ทดสอบ migration 012 ในฐานข้อมูลทดสอบก่อน
2. ใน Supabase SQL Editor ของโครงการที่ใช้งาน เปิด query ใหม่ วางเนื้อหาไฟล์ 012 ทั้งหมดและ Run ไฟล์ครอบด้วย transaction อยู่แล้ว
3. รัน `supabase/checks/012_verify_raid_lobby.sql` เพื่อตรวจชื่อฟังก์ชัน สิทธิ์ และการไม่สุ่มช้อย (อ่านอย่างเดียว ไม่แสดงคำตอบหรือข้อมูลนักเรียน)
4. เมื่อติดตั้ง SQL สำเร็จแล้วจึงนำโค้ดชุดนี้ขึ้น GitHub/ระบบ deploy ตามที่ผู้ดูแลอนุญาต
5. ลองห้อง Boss Raid ใหม่: เลือกทีม → ยืนยัน → เปิดทีมของฉัน → เปลี่ยนชื่อ → ตรวจหน้าครู → เริ่มเกม → ตรวจช้อยกับชุดที่ครูสร้าง

เกมที่กำลังเล่นอยู่ก่อนรัน SQL จะคง `option_order` เดิมเพื่อไม่เปลี่ยนช้อยกลางคำถาม ห้องที่เริ่มหลังติดตั้ง SQL ใช้ลำดับช้อยใหม่ ลำดับคำถามที่บันทึกไว้และประวัติคำตอบไม่ถูกแก้
